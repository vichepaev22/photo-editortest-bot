# Прототип Telegram Serverless: передача фотографии

Подготовлен 2026-10-08. Это изолированный тест транспорта без OpenAI и без списания генераций. Основной Python-бот, его SQLite, фото и три бесплатные попытки не затрагиваются.

`tgcloud/handlers/message.js` принимает свой JPEG/PNG в личном чате, проверяет размер до 10 MB и сигнатуру, получает bytes через SDK и возвращает документ тому же пользователю. `schema.js` хранит только идентификаторы события и статус. Уникальный ключ пользователь:сообщение захватывается до скачивания: повтор update не должен повторно отправлять файл. Неопределённый исход отмечается `review`; прерванный `started` тоже требует ручной проверки.

Фото не записывается в нашу БД. Однако это возврат исходных bytes: EXIF и содержимое не нормализуются. Проверка сигнатуры не заменяет декодирование изображения и защиту от огромного количества пикселей. Для первого облачного теста нужен только маленький синтетический PNG, не личный снимок.

Одна проверка локально, из корня основного репозитория:

```powershell
node experiments/telegram-serverless/check.mjs
```

Проверка использует подменённые SDK/БД. Она подтверждает логику ограничения размера, собственного чата и обработки дубликата в ядре; не доказывает работу настоящего SDK, SQLite платформы, webhook, лимитов или OpenAI. Node нужен только для этого локального скрипта. Облачные модули импортируют официальный `sdk`, не Node/npm.

Облачный этап ещё не выполнен. Для него нужен **отдельный тестовый бот**: BotFather → его настройки → Serverless → CLI Access → Access token. Нужен платформенный токен `app<id>:<secret>`, не обычный Bot API token. Ввод — через официальный CLI локально, не в исходник/чат. `.tgcloud/` и `node_modules/` исключены из Git. Без проверки назначения бота не запускать `push`, `migrate` или `webhook sync`: управляемый webhook конфликтует с polling рабочего бота.

Порядок будущей проверки: убедиться в ID тестового приложения; просмотреть diff и dry-run миграции; развернуть только этот probe; проверить повтор одного update и статусы БД на синтетическом файле. Наличие `tgcloud.jsonc` не означает, что приложение уже авторизовано или развёрнуто. После теста проверить и очистить данные тестового приложения штатными средствами платформы. Полный ledger/квота, TTL, согласие, удаление, очередь, платежи и Mini App пока не портированы.

План и ограничения: [telegram-serverless-migration.md](../../docs/telegram-serverless-migration.md). Контракты сверены с [официальным руководством](https://core.telegram.org/bots/serverless), публикацией [`@tgcloud/cli` 0.2.0](https://www.npmjs.com/package/@tgcloud/cli) и публичным [описанием возможностей платформы](https://cloud.telegram.org/capabilities).
