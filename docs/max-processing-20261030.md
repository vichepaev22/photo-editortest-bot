## Что изменилось

Во время генерации бот обновляет одно сообщение каждые~4секунды: очередь,
подготовка, изучение примера (когда нужно), генерация, файл и отправка.
Показывает фактически прошедшее время, последние3завершённых этапа.
Короткие этапы могут пройти между обновлениями; искусственного ожидания нет.
Это обычное текстовое сообщение, не новая картинка и не Thinking API Telegram.

Для медленного получения/подготовки фото или разбора пожелания статус появляется
после0,6с и превращается в итоговую карточку. Длинная карточка раскрывается в
том же сообщении двумя правками. Короткие мгновенные ответы не задерживаются.
Приветствие и инструкция сохраняют прежний постепенный показ.

Ответы и готовый файл получают link.type=reply к исходному доверенному событию
того же пользователя в личном диалоге. Новая реплика не меняет привязку уже
подтверждённой генерации. Связь в RAM ограничена сроком/объёмом; после рестарта
обычная доставка. Однозначный message.not.found допускает fallback без reply;
неизвестный исход POST не повторяется. Обновления идут с notify=false.

Новый ввод закрывает только старый UI, не Image и не резерв. Ошибка генерации
обновляет существующий статус и сохраняет прежний возврат. Ошибка доставки
сохраняет готовый файл для «Моих результатов» и не повторяет Image. Shutdown
закрывает задачи. После успешной доставки прежняя очистка только известных
собственных bot-step ID сохраняется. Клиентскую прокрутку не контролируем.
