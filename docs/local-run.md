# Локальный бот @photo_editortest_bot

2026-10-07. Ключи сохранены владельцем в локальном .env; документ секретов не содержит. Сервер/VPS пока не нужен.

## Быстрый тест

Дважды нажать `start-demo.cmd` в корне проекта либо запустить из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Bot.ps1 -Mode Demo
```

Процесс работает в фоне без дополнительного окна. Открыть https://t.me/photo_editortest_bot → `/start` → принять условия → `/demo` → выбрать функцию → отправить фото (для объединения два) → описание → подтвердить. После `/start` появляется нижняя клавиатура: изменить фото, объединить, попытки, результаты, помощь, поддержка. `/demo` выдаёт 3 тестовых кредита один раз. Обычная правка стоит 1, объединение — 2. Демо возвращает исходное фото с надписью **DEMO / NO AI EDIT**, настоящего изменения нет. Вызовов генерации OpenAI и их оплаты в этом режиме нет.

Тот же процесс открывает локальную Mini App: http://127.0.0.1:8089/ . В обычном браузере используется отдельный тестовый пользователь и баланс, в Telegram — подписанный вход. После настройки MINI_APP_URL кнопка меню «Студия» открывает GitHub Pages. До подключения внешнего API эта страница показывает предпросмотр; нативная клавиатура бота продолжает работать. Подробности: [mini-app.md](mini-app.md).

## Проверить состояние / остановить

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Status-Bot.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Stop-Bot.ps1
```

Статус содержит только PID, режим, состояние, имя бота и время записи. ОС удерживает один lock на проект: второй экземпляр не запускается. Остановка штатная, через локальный запрос; другие Python-процессы не завершаются. Компьютер должен быть включён и подключён к сети. Автозапуск при входе Windows пока не настроен.

## После пополнения OpenAI

Остановить демо, затем запустить:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Bot.ps1 -Mode OpenAI
```

Загрузки и баланс DEMO находятся в `data/demo`, рабочий пилот — в `data/live-pilot`. Они не переносятся друг в друга. Выбранная в .env модель/quality сохраняется; ключи не меняются. В режиме OpenAI `/demo` не выдаёт бесплатные кредиты. Владелец вводит свой `/id` в боте, подтверждает условия, затем локально выдаёт небольшой пилотный лимит:

```powershell
$env:DATA_DIR = 'data/live-pilot'
.\.venv\Scripts\python.exe -m image_studio pilot-credits --user-id ВАШ_ID --amount 3
Remove-Item Env:DATA_DIR
```

Сначала одна подтверждённая генерация, затем оценка качества и usage. Запуск OpenAI режима сам не вызывает генерацию: платный запрос происходит после пользовательского подтверждения заявки. Отсутствие средств/квоты возвращает резерв, нового запроса автоматически нет; перехода на демо вместо ошибки тоже нет. Покупки и внешний billing отключены в обоих локальных режимах.

## Диагностика

`data/runtime/stderr.log` — локальный журнал; `status.json` — состояние. Handler и provider ошибки выводят безопасные коды, фото/описания/ключи не предназначены для журнала. Не публиковать .env и каталог data.

При активном webhook запуск откажется: он не удаляется автоматически. Токен проверяется на ожидаемое имя бота. Готовность стартового сценария подтверждает getMe, getWebhookInfo, регистрацию команд и доступ getUpdates; фактическую доставку фото должен подтвердить пользовательский проход.
