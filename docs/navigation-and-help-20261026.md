## Поведение

- Telegram MAIN теперь is_persistent=true, one_time_keyboard=false. Ряды/цвета сохранены. Меню устанавливается приветствием и не удаляется обычными inline-сообщениями. После обновления пользователь один раз отправляет /start, чтобы клиент получил новый markup. [Bot API](https://core.telegram.org/bots/api#replykeyboardmarkup) просит клиент показывать эту клавиатуру, когда буквенная скрыта; нельзя запретить человеку вводить текст или управлять экраном клиента. Явный /delete сохраняет прежний сброс.
- «Как пользоваться»/help и «Инструкция» открывают три пары печатающийся текст→PNG вместо видео в чате. Фотографии/описание/запущенные Image-задачи не сбрасываются. Старое «Продолжить» в ранее отправленном Telegram-видео поддерживается; ранее доставленные видео не удалялись.
- MAX получил те же исходные три PNG, подписи для его интерфейса, вход из help и последней entry-карточки, фразу «Открой основное меню». Главное меню — на последней картинке, без повторов между парами. Новое событие/start/shutdown останавливает остаток инструкции. В MAX [документирована inline-клавиатура](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard), поэтому фиксированная нижняя reply-панель и Telegram-цвета не заявляются: меню остаётся под сообщениями. Рисованные Telegram-подобные интерфейсы в PNG — иллюстрации владельца; текст MAX не обещает расположение «Студия» слева.
- Внутри студии сохранено существующее интерактивное SVG/React motion-вступление с рабочими «Начать пользоваться», «Пропустить» и reduced-motion. Автоматический показ: первый вход или открытие страницы после 7 суток без посещений. Этот срок выбран как обратимое рабочее значение для «давно» и сообщён владельцу. Отсчёт от последнего посещения, не от просмотра анимации. Закрытое в текущем открытии вступление само не повторяется; ручное «Знакомство со студией» в профиле сохранено.
- Старый localStorage seen мигрирует без принудительного повторения всем; при отсутствии last-visit сохраняется текущий визит. Недоступное/повреждённое хранилище не блокирует вход. Состояние браузерное, зависит от устройства/домена/WebView, без привязки к серверному ID. Правило применяется при новом открытии страницы; уже открытое окно нужно закрыть и открыть вновь. Это не серверная синхронизация просмотров между устройствами.
- У Telegram VPS студии welcome.js и welcome.css возвращали HTTP404: добавлены два явных публичных маршрута, без wildcard/доступа к пользовательским файлам. MAX уже отдавал эти файлы. Одинаковый обновлённый welcome.js и index cache-version20261026-guide2 опубликованы в обоих VPS frontend и GitHub Pages. Новое видео не рендерилось.
