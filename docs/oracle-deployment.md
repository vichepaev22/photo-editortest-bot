# Перенос на Oracle Always Free

Статус на 2026-10-08: подготовлены установщик и systemd unit. Консоль Oracle пока показывает вход; владелец выбрал существующий аккаунт. VM, сетевые правила и ключ SSH ещё не созданы, серверная установка не запускалась. Локальный бот продолжает обслуживать пользователей.

## Ресурс и границы бесплатности

Первый вариант — **VM.Standard.A1.Flex, 1 OCPU, 4 GB RAM, Ubuntu 24.04, boot volume 50 GB**, только в home region. Перед созданием проверить Always Free-eligible и суммарное использование tenancy: опубликованный лимит A1 — 1 500 OCPU-hours / 9 000 GB-hours в месяц, эквивалент 2 OCPU / 12 GB; boot и block volumes вместе — 200 GB. [Официальные лимиты Oracle](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

Свободная ёмкость может отсутствовать. Малозагруженную VM Oracle вправе изъять; это существенное ограничение для пилотного бота. При отказе capacity проверить другой availability domain в home region; платный upgrade, новый регион или ресурсы сверх лимита не являются автоматической заменой. [Условия Free Tier](https://www.oracle.com/cloud/free/faq/).

Бот общается с Telegram исходящим polling, поэтому для первого переноса ему не нужен публичный HTTP. FastAPI слушает только `127.0.0.1:8089`. Для администрирования нужен SSH с ограниченным источником либо OCI Bastion. Открытие API и HTTPS для Mini App — следующий отдельный шаг после проверки сервера; Pages до него остаётся предпросмотром.

## Подготовленная установка

Исходники: `deploy/oracle/install.sh`, `image-studio-bot.service`, `server.env.example`. Установщик принимает **полный SHA уже опубликованного проверенного коммита**, а не изменяемое имя ветки:

```bash
sudo bash install.sh <FULL_PUBLISHED_COMMIT_SHA>
```

Скрипт рассчитан на свежую Ubuntu 24.04, устанавливает Python 3.12 и зависимости из `requirements.lock`, проверяет checkout SHA и создаёт отдельного пользователя `image-studio`. Код и venv принадлежат root. Данные доступны на запись только в `/var/lib/image-studio-bot` и `app/data/runtime`; последний каталог нужен существующему механизму lock/status. Реальные ключи хранятся в `/etc/image-studio-bot.env` с правами 0600. Установщик **не включает и не запускает** сервис: до переноса БД это создало бы второй polling и новую пустую квоту.

Подготовка файлов и shell syntax не подтверждают установку ARM-пакетов, доступность выбранной модели из региона или работу systemd на настоящей VM. Эти проверки выполняются после появления сервера.

## Переключение одного бота

1. Войти в существующую tenancy, проверить home region, текущие free allocations и наличие A1. Зафиксировать выбранный ресурс и отсутствие платных компонентов до создания.
2. Установить проверенный релиз на VM, оставить сервис остановленным. Через SSH передать текущие ключи отдельно от исходников. Сохранить модель, качество, trial=true, demo=false, billing=false. Не переносить Windows localhost proxy.
3. С VM выполнить только read-only Telegram identity/webhook и OpenAI model lookup. Это проверка сети и ключей; не тест генерации и не проверка баланса. При ошибке регионального доступа перенос не завершать.
4. Дождаться `queued=0/running=0`, штатно остановить локальный процесс. Создать согласованную SQLite backup через backup API и закрытую копию media с сохранением mtime. Не копировать работающие `db.sqlite3`/WAL как произвольные файлы. Локальный оригинал и `.env` оставить для отката.
5. На **копии для переноса** привести разделители путей Windows `\\` к `/`: только `jobs.result`, `inputs` в принадлежащих задачам JSON и `recent-inputs.json`. Фото, prompt, ledger, квоту и согласие не менять. Пути сохраняются относительно media; проверить владельца, отсутствие `..` и наличие каждого файла. Эту адаптацию нужно сделать при фактическом переносе: исходные записи Windows напрямую на Linux непереносимы.
6. Передать snapshot/media по SSH, установить владельца `image-studio` и закрытые права. Сравнить количество записей и все financial/trial поля, статусы задач и согласие до/после. Не начислять пользователям новую квоту и не запускать автоматически задания со статусом `review`.
7. Только после этих проверок выполнить `sudo systemctl enable --now image-studio-bot`. Проверить `is-active`, runtime ready, localhost health/catalog и отказ анонимного demo-session; Image-вызов не требуется. Затем пользователь делает следующий обычный тест в Telegram.

Для отката сначала остановить cloud service, затем запустить локальный бот с сохранённой БД. После новых cloud результатов откат требует свежей обратной копии ledger/media; старый snapshot нельзя выдавать за актуальный остаток попыток.

## HTTPS и дальнейшее обслуживание

Для рабочей Mini App нужны реальный домен/HTTPS reverse proxy, доступные только studio routes и разрешённый origin Pages. Нельзя подставлять IP с неподтверждённым сертификатом или публиковать 8089 целиком. Домен владельца ещё не выбран. Настройку Pages API URL делать после проверки Telegram initData через настоящий внешний адрес.
