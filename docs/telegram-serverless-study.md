# Telegram Serverless: применимость для «Образа»

Исследование 2026-10-08 по [официальной документации Telegram Serverless](https://core.telegram.org/bots/serverless). Страница прочитана в браузере: web parser её не разобрал. Дополнительно проверена публикация `@tgcloud/cli` **0.2.0**, Node ≥18, и статические файлы SDK/API внутри npm tarball. CLI не запускался, вход, deploy, миграции БД и переключение webhook не выполнялись. Это исследование, не работающий cloud PoC.

## Что подтверждено

| Возможность | Документированный контракт | Значение для проекта |
|---|---|---|
| Исполнение бота | JavaScript в V8 sandbox; SDK и собственные `.js` модули | Python/aiogram/Pillow напрямую не переносятся; в runtime нет npm-пакетов и файловой системы |
| Bot API | `api.sendMessage`, callback, клавиатуры и остальные методы; `BotApiError` | Нативный интерфейс можно сохранить, не используя aiogram |
| Получение фото | `api.getFileContent(file_id)` → Uint8Array, `getFileStream`; download cap 20 MB | Наши входы до10 MB укладываются; нормализацию/EXIF нужно отдельно заменить |
| Отправка файлов | `InputFile(bytes, name, {type})`, multipart на любой глубине | Можно доставить JPEG в чат или документом; действуют Bot API limits |
| Внешний HTTP | `sdk.fetch`, FormData/InputFile/Uint8Array request, JSON/text/stream response | По контракту можно сформировать multipart Images edit к OpenAI; реальная совместимость и задержка не измерены |
| Размер ответа | Всего не более30 MB, включая stream | Base64-ответ OpenAI должен помещаться вместе с JSON; приблизительно22,5 MB исходных bytes — верхняя оценка, не рабочая квота |
| База данных | SQLite-backed, query builder, unique/check/index, `.returning()`, BLOB Uint8Array | Можно хранить пользователя, квоту, задания и байты фото; размер БД/backup/TTL ещё требуют проверки |
| Целостность БД | Foreign keys отключены; DSL `references`/`foreignKey` отклоняется | Связи и удаление нужно контролировать прикладной логикой |
| Mini App HTTPS | С6октября2026 статическая сборка размещается на `https://app<app_id>.tgcloud.ai/` | Может заменить Pages и отдельный хостинг фронтенда |
| Endpoints | `endpoints/<name>.js`, `Telegram.WebApp.Serverless.call`, платформа проверяет initData до вызова, invalid→401 | Можно получить доверенный user из `ctx.initData`, но проверка принадлежности задания всё равно наша |
| Deploy | CLI push, ревизии, отдельный migrate и dry-run | Схему и исходник нужно выкатывать согласованно; полный push может удалить отсутствующие модули |

Это обычный поддерживаемый интерфейс Telegram, а не возможность произвольного CSS в нижней клавиатуре. Для её цвета остаются документированные `primary/success/danger`; произвольный дизайн доступен внутри Mini App. [Bot API](https://core.telegram.org/bots/api#keyboardbutton), [Mini Apps](https://core.telegram.org/bots/webapps).

## Доступ и риск переключения

Для Serverless нужен **отдельный токен** формата `app<id>:<secret>`, получаемый после включения в BotFather. Нынешний Telegram Bot API token его не заменяет. CLI сохраняет его в `.tgcloud/credentials` либо читает `TGCLOUD_TOKEN` для CI. Это credential управления платформой; его нельзя выдавать за хранилище ключа OpenAI.

Serverless использует управляемый webhook. `webhook sync` действительно перепривязывает адрес бота; это подтверждено и SDK docs, и `src/api/endpoints.js` опубликованного CLI. Для текущего @photo_editortest_bot это конфликтовало бы с локальным polling. Исследование не включает активацию на рабочем боте: для PoC нужен отдельный бот или согласованное переключение после подготовки миграции.

## Что пока не установлено

В прочитанном официальном руководстве и SDK-reference нет достаточного контракта для следующих вещей:

- цена, free tier, месячные квоты и условия начисления платы;
- wall-clock/CPU/memory limits обработчика и timeout внешнего fetch; отсутствие timeout в клиентском коде CLI не доказывает длительность cloud runtime;
- отдельное защищённое хранилище server secrets для OpenAI; не следует встраивать ключ в публикуемые JS-модули;
- очередь, планировщик и гарантии завершения работы после ответа webhook;
- транзакция из нескольких операций, нужная существующему ledger; atomic single-statement SQL не заменяет автоматически `BEGIN IMMEDIATE` для всей операции;
- лимит persistent DB/BLOB, backup/restore, физическое удаление персональных фото и эксплуатационные гарантии.

Отсутствие описания не означает отсутствие функции. Эти пункты требуют ответа платформы или ограниченной проверки с настоящим доступом. Обещание «бесплатно и круглосуточно» сейчас не подтверждено.

## Практическое решение

Первый перенос текущего Python-бота готовим на Oracle VM. Serverless рассматриваем как альтернативу для следующего прототипа; JS-переписывание сейчас не нужно для пользовательских правок.

Минимальный PoC после разрешения перечисленных вопросов: на отдельном боте принять синтетический JPEG, получить bytes, сохранить ограниченный BLOB, вернуть документ; одновременно отправить два duplicate updates и проверить однократное резервирование/идемпотентность. Затем проверить настоящий Mini App endpoint без/с валидным initData и изоляцию пользователей. CLI `run --ctx` передаёт контекст **без проверки** и не является доказательством безопасности входа. Длинный fetch сначала проверять на контролируемом сервисе; платный Images edit — последним отдельным измерением, если остальные контракты пригодны.

Пакет исследования скачан из официального npm registry с `--ignore-scripts` в ignored runtime, без исполнения CLI и без передачи ключей. В репозитории остаётся только эта записка, не tarball/credentials.
