# Образ — основное техническое задание / PRD v0.8

Обновлено: 16.10.2026. Этот файл — основной источник действующих требований. При каждой правке владельца сначала обновляются соответствующие пункты этого ТЗ, затем затронутый контракт/план и реализация. Узкие документы уточняют пункты, но не заменяют их. Исторические CR в конце не отменяют текущие требования. Подтверждённую готовность фиксирует отчёт приёмки, а не наличие записи в ТЗ.

## Продукт, инфраструктура и доступ

Русскоязычная фотостудия «Образ ·» для совершеннолетних в Telegram: @obraz_photo_bot. Нативный бот работает на VPS Play2go как один systemd-процесс с постоянной SQLite WAL; Mini App опубликовано на GitHub Pages и обращается к защищённому HTTPS API того же VPS. Ключи, фотографии и статистика не публикуются в Pages/Git. Локальный запуск остаётся инструментом разработки; второй production-poller одновременно не запускается.

SDK: Python 3.12+, aiogram 3, официальный OpenAI Python SDK, Pillow и pillow-heif. Действующий Image snapshot — gpt-image-2.5-flare-2026-09-08, quality=medium, size=1024x1024, n=1; изменение модели/качества требует отдельного решения. ChatGPT-подписка, Codex и Image API имеют отдельные способы доступа и бюджеты. Разработка далее выполняется через GPT-6.1 Sol. По указанию 10.10.2026 текущая админская задача выполняется ведущим агентом без субагентов, с коротким предметным контекстом и необходимыми проверками.

## R01–R06: обработка фотографий

1. Причёска, одежда, очки, фон, улучшение качества, объединение двух фотографий и «Фото на документы». Для каждой функции свои краткие подсказки и копируемые примеры. Причёски: можно запросить 1–12 вариантов в одном изображении; это рекомендация, а не гарантия API. Один готовый коллаж — одна генерация.
2. Загрузка фото/документа в Telegram и фото с галереи/камеры iPhone в Mini App: JPEG, PNG, WebP, HEIC/HEIF. До 10 MB (10 000 000 байт) на файл, до 64 MP перед декодированием. HEIF преобразуется сервером в JPEG, ориентация исправляется, EXIF/GPS удаляются. Предпросмотр не должен блокировать успешно загруженный файл; реальная проверка gallery/camera на iPhone фиксируется отдельно.
   CR-UPLOAD-002, 12.10.2026, accepted/implemented/verified/published (4bd5d9f): JPEG/MPO принимается как основное
   изображение; некорректный ICC в декодируемом HEIF не отменяет фото. Только после
   подтверждённого API invalid_image клиент может один раз подготовить JPEG через
   браузерный декодер/Canvas и загрузить его; при сетевой неопределённости автоматического
   повторного POST нет. Лимиты, согласие, владение и удаление метаданных сохраняются.
   Загрузка/преобразование не расходуют генерацию. Причина конкретного пользовательского
   файла пока не доказана; MPO-отказ воспроизведён отдельно.
3. Перед работой — согласие на обработку собственных фото и права/согласие каждого изображённого человека. Step1 предлагает новое фото или прежний доступный исходник, подсказку о файле и селфи у нейтральной стены. Ответ на своё фото в этом чате тоже выбирает его; само выбора фото генерацию не запускает. Для объединения нужны два исходника.
4. В текущем пробном чате описание автоматически запускает обработку после краткого Step3, без дополнительной кнопки. Mini App сохраняет явное подтверждение. Одна активная задача на пользователя; резерв до Image API, списание после сохранения результата, освобождение при ошибке. Дубликат запроса не запускает модель повторно. Interrupted running переводится в review без автоматического платного повтора.
5. Результат — файл с сохранённым качеством; повторное скачивание бесплатно и без нового Image-вызова. При успешной Telegram-доставке сохраняется `document.file_id` отдельно для bot ID, владельца и конкретного результата; повторная выдача использует этот ID. Проверки владельца, согласия, локального файла и 24 часов действуют и для кэша. Явно отклонённый Telegram file_id заменяется одной загрузкой сохранённого файла. Ответ 429 сохраняет срок следующей разрешённой отправки; повтор возможен по явному запросу результата после этого срока, без фонового повторения и генерации. Неопределённая сетевая ошибка автоматически не повторяется. Контракт CR-018: [result-delivery.md](result-delivery.md). Фото и результаты локально хранятся 24 часа, кроме незавершённых/review до разбора. /delete удаляет локальные фото и отзывает согласия; учёт операций остаётся. Удаление не распространяется на уже отправленные сообщения Telegram и данные провайдера. После доставки удаляются только собственные сообщения шагов этой заявки; исходники и результат пользователя сохраняются. Во время обработки обновляется штатный индикатор отправки фото.
6. «Фото на документы»: одна фотография, четыре одинаковые копии 2×2, 35×45 мм, PNG 826×1062/300 DPI; выбор нейтральной одежды и вариант подготовки исходника без ИИ. В варианте ИИ один вызов Image. Приём конкретным ведомством не гарантируется. Узнаваемость человека — критерий оценки, а не гарантия модели. Водяная метка отложена до отдельного решения о названии.

## R07–R10: бесплатные генерации, покупка и поддержка

7. Каждый обычный пользователь получает одну стартовую бесплатную генерацию один раз. CR-FREE-005 (15.10.2026, accepted/implemented/verified-offline/deployed; первая периодическая доставка 20.10.2026): дополнительно одна бесплатная генерация каждые пять суток; накопление регулярных бесплатных попыток вместе с неиспользованной стартовой — максимум три, включая резерв. Купленные, ручные начисления и отдельный однократный бонус за подписку не уменьшаются этим лимитом. Сначала расходуется стартовая попытка, затем регулярные бесплатные, затем купленные/дополнительные. Расписание индивидуальное: существующим пользователям первый срок через пять суток после включения функции, новым — после первого посещения. На каждом сроке приходит уведомление: о начислении либо о достигнутом лимите; нет обещания +1 при полном запасе. Простой сервера не создаёт пачку старых уведомлений; пропущенные сроки учитываются до лимита. Повтор /start, удаление фото, перезапуск и повтор задания не сбрасывают дату или лимит. Telegram и MAX имеют отдельные данные и расписания; в MAX это заменяет прежний запрет регулярной бесплатной выдачи, но не вводит новую стартовую попытку. Любая функция, объединение и перегенерация расходуют одну попытку за готовый результат. Ошибка не расходует попытку. Существующие оплаченные/ручные остатки и история не сбрасываются. Безлимит тестирования доступен только приватно настроенному ID владельца; согласие, одна активная задача и статистика для него сохраняются. Неопределённая доставка уведомления автоматически не повторяется; начисление от доставки не зависит. Отзыв согласия приостанавливает начисления и сообщения без обнуления остатка и без накопления за паузу. Старые адресные запреты автоматического продления заменены этой общей политикой.
8. После расхода первой попытки бот предлагает ещё одну за подписку одновременно на @FutureDarkSide и @nofuturenews: две ссылки и «Проверить подписку». В том же уведомлении после первой бесплатной попытки объясняется правило «+1 каждые пять дней, максимум три» и предлагается заходить почаще. Только подтверждённая подписка на оба канала даёт +1 один раз за всё время; отсутствие подписки понятно сообщается. Повторная проверка, выход/вступление, /start и перезапуск не продлевают бонус. Далее доступны приобретение пакета и регулярная бесплатная выдача R07. Это не подарок десяти генераций: десять были отдельным ручным начислением конкретному тестировщику.
9. CR-PLATEGA-001 (16.10.2026, accepted/implemented/verified-offline/deployed; реальная оплата 1 ₽ по СБП проверена 16.10.2026): по прямому указанию владельца Telegram использует внешнюю форму Platega, без реализации Stars. Пакеты: Express — 160 ₽ (5), Базовый — 380 ₽ (12), Premium — 790 ₽ (30). Один редактируемый экран: тариф → СБП/крипта → ссылка Platega и проверка оплаты → подтверждение либо отмена экрана. СБП success, крипта primary, правовые кнопки нейтральные внизу. Ключи только в приватных файлах/на VPS. Цена, пакет и получатель задаются сервером. Начисление только после проверки канонической транзакции у Platega, суммы RUB, магазина, transactionId и связи с собственным заказом; повторные callback/check/restart не удваивают начисление. Подписочный/стартовый/регулярный бесплатный доступ, старые остатки и действующий резерв сохраняются; покупка во время обработки не теряет стартовую попытку. Доставка подтверждения и событие владельцу надёжны и не условие начисления. Callback URL — отдельный публичный HTTPS POST на VPS; return URL и кнопка «Я оплатил» не доказывают оплату. Резервная сверка GET работает при потере callback. Неопределённый POST создания не повторяется автоматически. Срок берётся из expiresIn Platega, фиксированные 60 минут относятся только к старому демо. Chargeback замораживает дальнейший расход для ручного разбора, без автоматического банковского возврата. Официальное требование Telegram Stars для цифровых услуг сохраняется; внешняя форма не устраняет платформенный риск. Выбор Platega — явное решение владельца после разъяснения 16.10, не заявление о соответствии правилам Telegram. MAX в этой задаче не меняется. Двухмесячное ограничение и автоподписки не вводятся. Отключённый режим и старый YooKassa sandbox остаются отдельными.

Нижняя клавиатура нейтральная, только поддержка зелёная; стандартное сворачивание/вызов Telegram. «Купить / продлить доступ», баланс, результаты, помощь и функции доступны понятной навигацией, основные сценарии — за два нажатия до выбора функции. Поддержка ведёт на @nedelsky. Приветствие «Образ · ваша фотостудия» с упоминанием фото на документы, без пласта служебных команд. Формулировка возраста — «для совершеннолетних», без цифровой маркировки возраста.

CR-PLATEGA-002 (16.10.2026, историческое требование; заменено CR-PLATEGA-004): отдельный настоящий проверочный платёж «Проверка оплаты — 1 ₽ (1 генерация)» доступен только настроенному владельцу в Telegram. Ограничение проверяется сервером и при создании заказа, а не только скрытием кнопки; ID не записывается в исходники. Обычные тарифы сохраняются. Подтверждённая оплата начисляет одну генерацию один раз через общий платёжный учёт и уведомления. Неподтверждённая оплата не начисляет. API и callback остаются теми же; MAX не меняется. Context7 `/websites/platega_io`, 16.10.2026: явный минимальный платёж для методов 2/13 не найден; принятие суммы 1 RUB провайдером проверяется отдельно. Автоматического увеличения суммы и перевода денег агентом нет.

CR-PLATEGA-003 (16.10.2026, accepted/implemented/verified-offline/deployed; платёж verified-live, меню на устройстве пользователя pending): исправить подтверждённый платёж, у которого каноническая сумма включает комиссию, и повторное открытие покупки. Для наблюдаемого ответа `comissionType=0` допускается только точное равенство «сумма провайдера − положительная комиссия = сохранённая цена заказа»; остальные проверки магазина, валюты, transactionId, payload и однократности сохраняются. Не принимать произвольную переплату/допуск или неподтверждённый статус. Callback сверяется с исходной либо проверенной полной суммой этой же транзакции. В ledger отдельно сохраняются полная сумма, комиссия и её тип, не меняя сумму/число генераций заказа. Официальная схема Platega содержит поля, но не раскрывает значения enum; эта ветка основана на реальном аутентифицированном ответе магазина (1,09 − 0,09 = 1 ₽, type0), это явно отмеченное наблюдение, а не выдуманный общий контракт. При нажатии нижней «Купить / продлить доступ» показывать текущий checkout новым видимым сообщением; шаги внутри покупки редактируют его. Старое активное окно удаляется по возможности и его кнопки отклоняются; текущий счёт/ссылка/статус не создаются повторно и переживают перезапуск. Подтверждённый старый чек сохраняется. Пояснять возможную комиссию Platega до перехода к оплате. Восстановить начисление уже оплаченного рублёвого заказа общим проверяющим механизмом без нового перевода.

## R11–R17: полная админская панель

11. /admin только владельцу по приватному ADMIN_TELEGRAM_ID в личном чате; повторная проверка на каждом callback и текстовом действии. Username не авторизует. Панель работает редактированием одного сообщения; ответы поиска/ввода параметров не попадают в описание фото или поддержку.
12. Все учётные записи и фактические посетители показаны раздельно. Список по десять, фильтры «все / заходили / покупали», поиск точного ID/@username. Кликабельный аккаунт. Карточка: доступно/резерв, начисленные и стартовые генерации, тип доступа/безлимит, канал-бонус, успешные генерации, реальные покупки/сумма, первый/последний визит, согласия. Даты UTC+5. Служебные кнопки админки различаются штатными цветами Telegram: навигация/поиск — синий, покупки и положительные действия — зелёный, уменьшение — красный. Кнопки отдельных пользователей/карточек нейтральны; пользовательская нижняя клавиатура сохраняет прежнее оформление.
13. +5, +10, −1, произвольное изменение и установка доступного остатка. Причина обязательна: собственный текст или кнопка «Таков путь» по умолчанию; перед применением предпросмотр «было → станет» и подтверждение/отмена. Подтверждение владельцу на пять минут, одно применение, устаревшее состояние отклоняется. Оплаченный резерв сохраняется, отрицательного остатка нет. При активном trial-резерве дождаться завершения. Безлимит владельца защищён от изменения этим инструментом. После подтверждённого увеличения остатка пользователю приходит сообщение с фактически добавленным количеством и пометкой администратора. Предпросмотр, отмена, уменьшение и повтор подтверждения не создают такого сообщения.
14. Постоянный журнал изменений: исполнитель, пользователь, причина, время, остатки до/после, резерв, статус и операция. Перезапуск, /delete и истечение фото не очищают учёт.
15. Уведомления только владельцу: первое реальное посещение один раз; начало, успех, ошибка/review генерации; новый подтверждённый production-платёж после зачисления; необработанные сообщения вне выбранного сценария редактирования. Демо/тестовые платежи, повторная выдача фото и старые события не создают новые уведомления. Вопросы ограничены по длине/частоте, пользователь получает понятный ответ о передаче.
16. «События» — история, полное обращение и сведения задания. «Уведомления» — категории и общая пауза доставки владельцу. Durable outbox и квитанции; подтверждённая отправка не повторяется, известная временная ошибка допускает ограниченные повторы, неизвестный сетевой исход требует проверки. Уведомление о ручном начислении сохраняется в той же транзакции, что изменение остатка, доставляется только получателю этой операции и не зависит от паузы уведомлений владельцу. Ошибка отправки не меняет кошелёк/генерацию/выдачу; статус доставки доступен владельцу в «Событиях». Исторические начисления не рассылаются задним числом.
17. По умолчанию генерация видна как метаданные. /sharing — явное отдельное разрешение пользователя на просмотр описания и результата будущих заданий в течение 24 часов от создания; исходные фото не передаются. Отзыв закрывает доступ и удаляет описания, повторное включение не открывает историю. /delete отзывает оба согласия. Доступ к файлу повторно проверяет пользователя, задание, согласие, срок и безопасный путь.

Детали интерфейсов и ограничений: [admin-panel.md](admin-panel.md). **Публикации обновлений в двух каналах на паузе по указанию 10.10.2026**: нет активных кнопок, обработчиков или отправки; подготовку постов обсуждаем отдельно.

## Экономика, отложенные возможности и приёмка

Аренда сервера — 300 ₽/месяц со слов владельца, цель прибыли — 10 000 ₽/месяц. Себестоимость учитывать по фактическому usage Image, входам/выходу/качеству, курсу, комиссии, ошибкам и бесплатным попыткам. Пакет сам по себе не гарантирует прибыль. Расчёты — [financial-model.md](financial-model.md).
