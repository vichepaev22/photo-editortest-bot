# Образ — Product Requirements Document v0.2

Дата: 2026-10-07. Состояние: локальный MVP и интерфейс Mini App реализованы; коммерческий запуск требует live-PoC.

## Продукт и аудитория

Русскоязычный Telegram-бот: загрузить собственное фото, примерить причёску, одежду, очки, изменить фон или объединить два фото; купить фиксированный пакет попыток. Рабочее название «Образ» обратимо и не проверено на товарные знаки. Возраст 18+ — допущение MVP. Интерфейс короткий: выбор функции → 1–2 фото → описание → стоимость → подтверждение → файл.

Ценность: узнаваемость человека, понятная цена перед каждой операцией, удобное сравнение вариантов. «Сохранение лица» — критерий оценки, а не гарантия генеративной модели. Объединение не считается доказательством реального совместного события. Примерка не обещает физическую посадку одежды.

## Границы MVP

1. Меню: причёска, одежда, очки, фон, улучшение фото, объединение двух фото.
2. Фото JPEG/PNG/WebP до 10 MiB каждое, максимум два; декодирование, ограничение пикселей, удаление EXIF. Фото Telegram и документы поддерживаются; исходное качество предпочтительно через документ.
3. Пользователь подтверждает 18+, права/согласие изображённых людей и передачу изображений OpenAI перед редактированием. Для второго человека применимо то же согласие.
4. Причёска/одежда/очки/фон/улучшение: 1 кредит за один результат; объединение: 2 кредита. Новый вариант и дальнейшая правка оплачиваются отдельно. Остаток не может стать отрицательным.
5. Пакеты-гипотезы: 5 кредитов / 149 ₽, 10 / 249 ₽, 25 / 549 ₽. Это тестовые цены, продажи отключены по умолчанию. Пересмотреть после измерения p95 затрат.
6. По новому указанию пользователя Stars исключены из реализации. Внешний модуль ЮKassa (коммерческий сервис ЮMoney, выбран для sandbox после согласия на самый быстрый вариант) использует RUB и целые копейки. Неизменяемый заказ, проверка владельца/валюты/суммы, начисление только после проверки succeeded+paid через авторизованный API ЮKassa, уникальный payment_id. Webhook не считается доказательством оплаты. Модуль не публикует платёжные ссылки в Telegram: продажа таких цифровых услуг через сторонний сервис внутри бота противоречит правилам Telegram. Коммерческий сценарий требует отдельного решения; технический sandbox можно проверить независимо.
7. Одна незавершённая операция на пользователя, один worker; резервирование до вызова модели, списание после сохранения результата, освобождение резерва при отказе/ошибке. Подтверждения и задания идемпотентны; повтор фото фильтруется в текущей заявке. Полная долговечная дедупликация входящих событий не реализована.
8. Если результат уже создан, повторная доставка использует сохранённый файл. Нельзя повторно вызывать модель из-за ошибки Telegram. `/result ID` доступен только владельцу.
9. После падения процесса задача running переходит в review без автоматического повтора: провайдер мог уже обработать платный запрос. Поддержка разбирает резерв; CLI release-job освобождает его с журналируемым статусом. Очередь queued восстанавливается. Для завершённых/ошибочных задач локальные фото удаляются по TTL 24 часа. `/delete` удаляет локальные изображения и настройки согласия; финансовые записи остаются для учёта. Незавершённая задача требует завершения/поддержки перед удалением.
10. `/terms`, `/privacy`, `/support`, `/paysupport`, `/balance`, `/cancel`. Контакт владельца обязателен для платного режима; тексты условий предварительные, требуют реквизитов и проверки до продаж.
11. Тестовый провайдер возвращает явно помеченную DEMO-копию; это проверка процесса, а не качества ИИ. `/demo` даёт 3 тестовых кредита один раз только в mock-режиме при отдельном флаге.

12. Принятое расширение интерфейса: постоянная нижняя клавиатура из шести действий, цветная inline-сетка функций, подтверждение стоимости и список собственных результатов. Помощь и баланс сохраняют черновик; переход к новой правке отменяет старое подтверждение. Файл результата выдаётся повторно без нового вызова Image.
13. Mini App «Студия / Образы / Результаты / Профиль»: локальный авторизованный API использует тот же ledger и worker. Вход Telegram проверяется HMAC; отдельный локальный DEMO-пользователь не связан с балансом владельца. Загрузка, описание, явное подтверждение цены, состояние задачи, сравнение и скачивание. Светлая/тёмная темы и адаптация под телефон.
14. По указанию владельца исходники публикуются на GitHub, интерфейс — на Pages. Пока API работает локально, Pages предоставляет предпросмотр без отправки фото и без генераций. Доступный извне HTTPS API добавляется при переходе на VPS. Изображения оформления предоставляет владелец по отдельному ТЗ; самостоятельно они не генерируются.

Вне первой версии: подписки/безлимит, массовые рассылки, публичная галерея, видео, свободные промпты без выбранной функции, 4K, маски рисованием, встроенный конструктор тарифов, реферальные бонусы, автоматический возврат частично использованного пакета. Внешний модуль возврата ЮKassa поддерживает только полностью неиспользованный пакет и блокирует новые задачи во время операции; окончательное списание кредитов лишь после подтверждения succeeded возврата.

## Метрики и гипотезы

Визуальный PoC: минимум 12 заданий на согласованных фото, включая два лица/очки/чёлку/разный свет; оценка узнаваемости и точности по 1–5. Гейт: не менее 80% приемлемых результатов (оба критерия ≥4), отсутствие критического искажения личности, p95 latency ≤120 секунд как цель, p95 полной переменной себестоимости ≤40% чистой выручки за кредит. Это целевые пороги, не измеренные результаты.

Пилот спроса: 20–30 добровольцев, activation = загрузил фото и получил результат; конверсия в оплату ≥10% — гипотеза, repeat purchase ≥20% за 30 дней — гипотеза. Платный пилот начинается после доступности провайдера, качества, поддержки и проверки выплат. Любая реклама — отдельное решение.

## Безопасность и отказоустойчивость

Только личный чат. Ключи в локальном `.env`/секретах сервера. Нет фото, промптов и токенов в обычных логах. В БД только ID пользователя, баланс, состояния, безопасные коды ошибок, usage и request_id; пути только внутри data. Запрет раздетых/сексуализированных изображений, насилия/обмана — продуктовая граница; отдельная предварительная проверка текста/фото пока не реализована; стандартные ограничения модели остаются включёнными. Полная модерация входов перед коммерческим запуском требует отдельной реализации и проверки.

TTL касается нашей локальной копии; сообщения и файлы Telegram, данные у провайдера подчиняются их условиям. Не обещаем мгновенное удаление у третьих сторон. Для запуска обслуживать регионы в соответствии с [поддерживаемыми странами OpenAI](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories): Россия в списке не указана; язык интерфейса сам по себе не определяет географию пользователей. До определения допустимой аудитории и оператора публичный платный запуск остаётся закрыт.

## SDK и модель

Python 3.12+, aiogram 3 (официальный проект aiogram), официальный OpenAI Python SDK, Pillow; SQLite WAL для локального однопроцессного MVP. OpenAI Images API `images.edit`, `n=1`, явные quality=medium и size=1024x1024; Flare snapshot `gpt-image-2.5-flare-2026-09-08`. Для сравнения в PoC Sunburst, те же входы и настройки. Не добавляем текстовую модель в каждую операцию: промпты составляются из выбранной функции и описания. Версионный SDK может потребовать extra_body для свежих параметров; проверяем установленные типы.

Официальные модели: [Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare), [Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst). API и ChatGPT — разные способы доступа; встроенный генератор Codex не подтверждает биллинг или доступ проекта к API.

Уточнение выбора2026-10-07: официальное руководство рекомендует Sunburst, когда важнее точность редактирования, и Flare для быстрых повседневных генераций. Для примерки и сохранения личности основной кандидат — Sunburst; текущая конфигурация Flare/medium сохраняется до сравнительного PoC. Обе имеют одинаковые ставки за токен, но количество токенов и полная себестоимость результата требуют измерения. Не объявляем Flare дешевле без usage. Источник: [Image generation](https://developers.openai.com/api/docs/guides/image-generation).

## Приёмка и открытые вопросы

Исполняемые сценарии в `acceptance.md`; стадия и доказательства в `verification.md`. Для live-PoC: пополнение OpenAI и разрешённые тестовые фото. Для продаж: допустимые регионы/оператор, контакт поддержки, реквизиты/оферта, условия ЮKassa/чеков, разрешённый платёжный сценарий, эксплуатационные бюджеты, измеренный тариф. Ключи не присылать в чат. Локальный DEMO запущен; продажи и платный Image-PoC ещё не выполнены.
