# Контракт приёмки

| ID | Дано → действие → наблюдаемый результат |
|---|---|
| A1 | Новый пользователь → соглашается и загружает фото → JPEG без EXIF, до 2048 по длинной стороне, владение ограничено user_id |
| A2 | Баланс 1 → подтверждение обычной правки → резерв 1; баланс 0 → не вызывает провайдера |
| A3 | Баланс 1 → объединение → отказ; баланс 2 и два фото → резерв 2 |
| A4 | Два конкурентных подтверждения → одна active-задача и неотрицательный доступный баланс |
| A5 | Повтор одинакового request_key → тот же job_id, без повторного списания/вызова |
| A6 | Правильный платёж → кредитуется один раз; повтор charge_id / другой пользователь / currency / сумма → баланс не увеличивается |
| A7 | Провайдер отказал → резерв возвращён один раз; provider timeout → нет автоматического нового платного запроса |
| A8 | Результат создан, Telegram недоступен → файл хранится, повтор `/result` использует его и не оплачивает генерацию повторно |
| A9 | Другой пользователь → `/result ID` или чужой заказ → доступа нет |
| A10 | Рестарт → queued сохраняются, running→review; новые платные вызовы для review не происходят |
| A11 | `/delete` → локальные медиа удалены, согласие сброшено; active→обращение в поддержку; financial ledger сохранён |
| A12 | Измеренный usage → долларовая стоимость по text/image/output токенам; неизвестный usage→unknown, никогда 0 как подтверждённая стоимость |
| A13 | Mock → DEMO-маркер и нулевой внешний расход; live оплаты в mock запрещены |
| A14 | Возврат неиспользованного пакета → баланс заблокирован на время API и кредиты отозваны лишь после подтверждения succeeded ЮKassa; частично израсходованный пакет→ручная поддержка |
| A15 | Вне trial администратор локально выдаёт до10 пилотных кредитов пользователю с согласием → журнал; произвольная публичная выдача финансовых кредитов в OpenAI режиме отсутствует |

A1–A15: тесты домена и контрактов SDK, offline-PoC; полное покрытие сценариев не заявлено. Реальный Telegram и качество лиц — отдельные live-gates. ЮKassa тестируется с mock HTTP; реальный sandbox магазина требует ключей. На production шлюз не переводился.

## Три бесплатные генерации

В бесплатном режиме отдельная квота заменяет стоимость из A2/A3. Коммерческий кошелёк сохраняется.

| ID | Сценарий |
|---|---|
| T1 | Новый подписанный Telegram-пользователь → согласие → автоматически 3 генерации; повтор start/session/consent не добавляет ещё 3 |
| T2 | Причёска, новый вариант и объединение двух фото → три результата, каждый за 1; четвёртый запрос → trial_exhausted до вызова модели |
| T3 | Прежний баланс 3 или 100 кредитов → в trial всё равно максимум 3 результата; financial balance/reserved/spent не меняются |
| T4 | Двойное/конкурентное подтверждение → один резерв; одинаковый ключ → та же задача; изменение preset/cost/trial для того же ключа отклонено |
| T5 | Отказ модели → попытка доступна снова; ошибка доставки → готовый файл доступен без повторного вызова; running после рестарта → review с резервом |
| T6 | После трёх результатов → delete/reconsent/restart → остаток 0; другой пользователь имеет независимые 3 |
| T7 | Старая SQLite БД → добавочная миграция → сохранены кошелёк, согласие, задания и медиа; старые задания остаются коммерческими |
| T8 | OpenAI trial → анонимный demo-session запрещён; mock или enabled billing + trial → ошибка конфигурации; Demo launcher выключает trial только в своём процессе |

## Уточнения бесплатного чата после первого результата (CR-009)

| ID | Сценарий |
|---|---|
| N1 | Шаг 1 → файл до 10 MB (10 000 000 байт) или новое фото на нейтральном фоне; следующий байт сверх лимита отклоняется |
| N2 | Trial: принято описание → шаг 3 с функцией/ценой → одна задача без кнопки «Создать»; повтор того же сообщения не расходует вторую попытку |
| N3 | Выбор очков после причёски → использовать прежний исходник без загрузки; новый процесс восстанавливает ссылку на исходник предыдущей задачи |
| N4 | «Использовать загруженное фото» → повторная проверка владельца, согласия, файла и 24 часов; устаревшая кнопка не меняет новую заявку |
| N5 | Ответ на своё фото «возьми это фото» в том же личном чате → фото принято и шаг 2 без генерации; внешние/чужие ссылки не используются |
| N6 | Задача queued/running → обновляемый нативный индикатор; завершение/отмена runtime останавливает его; ошибка Telegram-индикатора не прерывает Image |
| N7 | Обработка/результат/ошибка → понятный текст без job ID; «Мои результаты»/«Скачать ещё раз» возвращают свой файл без расхода попыток |
| N8 | Прежний расход одной попытки → перезапуск после обновления → остаток две; коммерческое подтверждение и API контракт сохранены |

## Интерфейс и локальная Mini App

| ID | Сценарий |
|---|---|
| U1 | /start после согласия → шесть нижних кнопок; функции доступны через inline-сетку; шаг 3 содержит стоимость, в trial запускается автоматически, в коммерческом режиме требует подтверждения |
| U2 | Баланс/помощь во время заявки → описание и фото сохранены; подпись навигации не становится промптом; главное меню делает старое подтверждение недействительным |
| U3 | Мои результаты → только свои существующие файлы; чужой callback/HTTP ID недоступен; скачивание не вызывает провайдера |
| U4 | Mini App initData → подпись HMAC и свежесть проверяются сервером; подделка/устаревшие/дублированные поля отклоняются; ключи не передаются браузеру |
| U5 | Локальное демо → только loopback + mock + явное согласие; отдельный user=0, три попытки один раз; в OpenAI режиме endpoint закрыт |
| U6 | Mini App → фото, функция, описание, подтверждение → одно durable-задание; повтор request_key не создаёт вторую задачу; чужие фото и лишние входы отвергаются |
| U7 | 320/390/768/1440 px, светлая/тёмная тема → нет горизонтального переполнения, доступный ввод и кнопки; работают ошибки, ожидание, результаты и ползунок сравнения |
| U8 | Бот запущен локально → приложение отвечает на loopback; graceful stop закрывает оба сервиса; Mini App URL появляется в Telegram только при заданном HTTPS |
