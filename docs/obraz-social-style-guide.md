# Образ · ТЗ на единый стиль сторис, каруселей и анонсов

Версия 1.0 · 16 октября 2026. Основание — существующая приветственная анимация «Образа», её постер, исходники `motion/welcome/src/Scene.tsx`, `art.tsx` и `docs/welcome-motion-brief.md`. Применён навык social-media-designer. Это ТЗ для создания материалов владельцем: новые изображения и видео здесь не генерируются.

## Главное ощущение

Спокойная личная фотостудия: один человек пробует разные версии себя. Взрослая редакционная 2D-иллюстрация, молочный фон, белые карточки, глубокий зелёный акцент, мягкая мята и тёплые бежевые детали. Всё выглядит как продолжение существующей анимации, а не новая рекламная кампания с другим оформлением. Польза понятна по одному взгляду на изображение.

## Палитра

| Роль | Цвет | Применение |
|---|---|---|
| Основной фон | #F6F5F3 | Большая спокойная плоскость |
| Карточки | #FFFFFF | Рамки портретов, интерфейс, листы |
| Текст | #29343B | Заголовки, логотип, основной текст |
| Главный акцент | #176B5B | Точка логотипа, одна CTA, выбранный вариант |
| Мягкая мята | #E6F1EB | Подложки, небольшие выделения |
| Тонкая граница | #DCE0DF | Карточки, разделители |
| Приглушённый текст | #687972 | Подписи и пояснения |
| Тёплая подложка | #EEE4D7 | Небольшая вторая мягкая плоскость |

Ориентир по площади: 70% светлого фона, 20% белых карточек, до 10% акцентов. Это правило композиции, а не требование закрашивать фон по формуле. Синий — только небольшая деталь иллюстрации; он не становится цветом всех кнопок. Не использовать неон, кислотные градиенты, чёрные технологичные панели или обилие свечения.

## Типографика и логотип

В ролике используется Segoe UI с запасным Arial. Для ручной вёрстки сохранять этот шрифт, если он доступен в вашем редакторе; иначе выбрать один нейтральный гротеск с кириллицей и применять его во всей серии. Не смешивать семейства между карточками.

Логотип — «образ.» строчными: графитовые буквы и небольшая зелёная точка. Отдельный рисованный знак не нужен. На готовом материале логотип должен оставаться редактируемым текстом/вектором. Не просить генератор картинок рисовать точную надпись: текст лучше накладывать в редакторе.

Для холста шириной 1080 px: заголовок 64–88 px, пояснение 34–42 px, служебная подпись от 24 px. Заголовок 3–7 слов, обычно 1–3 строки. Один короткий поясняющий блок. Межстрочный интервал спокойный, без плотных текстовых стен.

## Иллюстрация и персонаж

Один узнаваемый взрослый персонаж в пределах истории: одинаковые лицо, ракурс, пропорции и цвет кожи. Смена причёски, оправы или одежды не должна превращать его в другого человека. Мягкие округлые формы, чистые контуры, простые плоские тени; допускается очень деликатный градиент кожи или ткани. Без фотореалистичного 3D, детских пропорций, сложного глянца и чрезмерной карикатуры. Палитра одежды — шалфей, бежевый, молочный, графит.

Людей можно менять между независимыми историями; внутри демонстрации «до/после» сохранять одного человека. Сложное изображение не должно конкурировать с заголовком. Рисованные результаты обозначать небольшой подписью «Иллюстрация возможностей», чтобы не выдавать рисунок за реальную генерацию бота.

## Общая композиция

Верх: небольшой логотип и короткое название функции. Ниже — большой заголовок. В центре — один главный объект: портрет, карточка или лист с фото. Внизу — одно пояснение и один следующий шаг. Много воздуха; мягкие скругления 28–40 px на холсте 1080 px, тонкая обводка 1–2 px. Лёгкая тень: 0 24px 68px rgba(39,61,50,0.10).

Фон может включать две полупрозрачные мятную/бежевую формы и редкие контурные мотивы: очки, рамка фото, лист. Они остаются по краям и не проходят через лицо или текст. Не более трёх смысловых групп на изображении: текст, демонстрация, следующий шаг.

## Как показывать функции

| Функция | Главная иллюстрация | Что сохранить |
|---|---|---|
| Причёски | Один портрет и сетка нескольких причёсок | Одно лицо, разные волосы; количество вариантов в иллюстрации не обещает фиксированный результат API |
| Очки | Один портрет и 2–3 простые оправы | Меняется оправа, лицо остаётся узнаваемым |
| Одежда | Один персонаж в двух комплектах | Это визуальная примерка, без обещания точного размера вещи |
| Фон | Портрет в одной рамке и смена окружения | Субъект остаётся в том же положении |
| Улучшение | Небольшой фрагмент до/после с более чистыми деталями | Не обещать восстановление отсутствующих деталей или идеальное сходство |
| Объединение | Две отдельные карточки плавно сходятся в одну сцену | Понятна связь двух исходников и общего кадра |
| По примеру | Маленькая карточка референса и большой итоговый портрет | Показать перенос позы/света/настроения с сохранением героя |
| Фото на документы | Один портрет превращается в лист 2×2 | Четыре одинаковых снимка; не обещать гарантированное принятие официальными органами |

Не помещать все восемь функций на одну карточку. Общий обзор может содержать компактные пиктограммы; подробная демонстрация — одна функция на кадр.

## Рабочие шаблоны

Это выбранные размеры макетов, а не утверждение об обязательных ограничениях площадок.

**Сторис:**1080×1920,9:16. Рабочее поле по горизонтали от x72 до 1008, по вертикали от y250 до 1600 для важного текста и CTA; края проверять в предпросмотре конкретной площадки. Один кадр — одна мысль. На изображении «Открыть Образ» — нарисованный CTA; настоящую ссылку/стикер добавлять при публикации. Переносить карточку карусели на сторис нужно перекомпоновкой, а не растяжением.

**Карусель:**1080×1350,4:5, одинаковый размер всех карточек. Поля 72 px. Каждая карточка — отдельный PNG/JPEG, а не один общий коллаж. Номер 1/7 размещать одинаково. Предлагаемая серия из 7 кадров: обложка «Один снимок. Разные образы.» → загрузка своего фото → причёски → очки/образ → объединение → фото на документы → финал «Теперь ваша очередь». Для серии про одну функцию: проблема → исходник → варианты → выбранный образ → как повторить → CTA. Это примеры структуры, не обязательный текст каждой публикации.

**Квадратный анонс:**1080×1080. Один крупный портрет/предмет, короткий заголовок, логотип. **Горизонтальный анонс:**1600×900, отдельная композиция с текстом слева и героем справа. Не обрезать вертикальную историю до горизонтального формата автоматически.

## Перевод движения в статичный кадр

Показывать один читаемый ключевой момент существующей анимации: фото уже в рамке, несколько причёсок уже разложены, выбранная оправа подсвечена, два фото собираются в общий кадр, лист 2×2 полностью сформирован. Намёк на движение — небольшое смещение карточки, мягкая дуга, 2–3 точки прогресса; без размытого лица и множества стрелок.

Для будущей анимации сохранить плавность текущего ролика: смена функции за 3–4 секунды, мягкое появление/перемещение за 0.4–0.7 секунды, без резких зумов и вспышек. Иконки фона двигаются едва заметно; во время результата почти стоят. Статичная версия должна быть понятна без анимации и без звука.

## Короткий бриф для копирования

«Создай отдельный вертикальный макет для бренда “образ.” в стиле приложенной приветственной анимации: взрослая редакционная 2D-иллюстрация, молочный фон #F6F5F3, белые округлые карточки, графит #29343B, глубокий зелёный #176B5B и мягкая мята #E6F1EB. Тема: [ФУНКЦИЯ]. Один узнаваемый взрослый персонаж, чистые контуры, плоские мягкие тени, много воздуха. Главный объект — [ДЕМОНСТРАЦИЯ]. Оставь свободное поле для заголовка [ТЕКСТ], короткого пояснения [ТЕКСТ] и нижнего CTA [ТЕКСТ]. Размер [ШИРИНА×ВЫСОТА]. Без неона, фотостокового коллажа, псевдотрёхмерного глянца и мелкого текста. Точные надписи и логотип будут наложены отдельно в редакторе».

К этому брифу прикладывать существующий постер/кадр ролика как референс. Для продолжения серии прикладывать также предыдущую готовую карточку, чтобы сохранить лицо и композиционные правила.

## Что передать на согласование

Сначала одна тестовая сторис и одна карточка карусели, затем серия. Исходник с отдельными слоями фона, персонажа, карточек, текста и CTA; SVG для иллюстраций по возможности. Экспорт sRGB PNG либо JPEG высокого качества, без лишних метаданных. Имена `obraz_story_hair_01.png`, `obraz_carousel_01.png`… Отдельно отмечать, где рисунок, а где настоящий результат бота. Цены, бонусы и ссылки проверять перед публикацией; в базовые шаблоны не зашивать меняющиеся акции.
