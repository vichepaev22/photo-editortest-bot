# Фото iPhone в мини-приложении

Цель: выбрать готовое фото из галереи или сделать новое через системный выбор фотографии, без ручного сохранения в JPEG. Точная кодировка файла, вызвавшего ошибку у пользователя, не установлена. Проверка исходников обнаружила два ограничения: отказ по клиентскому MIME и отсутствие HEIF-декодера на сервере. Старый лимит 24 MP уже был исправлен до 64 MP отдельно.

## Решение

`Галерея / камера → исходный файл → VPS → HEIC/HEIF-декодер → JPEG → предпросмотр / генерация`

- Мини-приложение допускает JPEG, PNG, WebP, HEIC и HEIF. Пустой или неточный MIME не блокирует загрузку: сервер проверяет содержимое. Системный выбор сохраняет доступ к галерее; отдельный режим камеры не навязывается.
- Сервер использует закреплённый `pillow-heif==1.8.0`, декодирует основное изображение с корректным поворотом и сохраняет JPEG без EXIF/GPS/XMP. Для HEIF с ICC-профилем цвет переводится в sRGB. Остаются пределы 10 MB и 64 MP, JPEG quality 92 и сторона до 2048 пикселей. HDR в таком JPEG не сохраняется.
- Декодирование загрузок выполняется вне цикла бота, по одному файлу. После ожидания повторно проверяются сессия, согласие и лимит файлов: отзыв согласия не позволяет сохранить новое фото.
- После загрузки превью берётся из подготовленного сервером JPEG через защищённый запрос. Неудача превью не отменяет принятую загрузку и не запускает повторный POST.

GitHub Pages отдаёт интерфейс, а файл обрабатывается на VPS. Для этого исправления перенос интерфейса с Pages не требуется. Загрузка и преобразование не вызывают OpenAI и не расходуют генерацию.

## Проверка и ограничения

Локально проверены настоящий синтетический HEIF, поворот, выбор основного изображения, удаление метаданных, повреждённый файл и ограничения. Проверен API-путь HEIF с неточным MIME → загрузка → JPEG-превью без обращения к модели. Проверен отказ сохранения при отзыве согласия во время декодирования; синтаксис JavaScript проверен отдельно.

На самом iPhone ещё нужны четыре короткие проверки в Telegram: HEIC из галереи, JPEG из галереи, новое фото камеры и скриншот PNG. Фиксируются версия iOS/Telegram и результат загрузки. Синтетический HEIF не доказывает совместимость каждой разновидности Apple HEIC/HDR/Live Photo; принимается основное неподвижное изображение, а не видео Live Photo.

Основание: [WebKit: HEIC в Safari и WKWebView](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/), [pillow-heif: установка](https://pillow-heif.readthedocs.io/en/stable/installation.html), [поворот HEIF](https://pillow-heif.readthedocs.io/en/stable/workaround-orientation.html), [AnyIO: обработка в потоках](https://anyio.readthedocs.io/en/stable/threads.html).
