# План переноса на Telegram Serverless

Дата: 2026-10-08. Пользователь поручил проработать перенос параллельно с диагностикой Oracle. Подготовлен изолированный [транспортный прототип](../experiments/telegram-serverless/README.md). Полный перенос и работа в облаке пока не подтверждены.

## Что переносим

| Сейчас | Вариант Serverless | Критерий готовности |
|---|---|---|
| Python/aiogram, шесть функций и цветная клавиатура | JavaScript handlers + SDK Bot API; тексты/стили сохранить | Те же функции и понятные шаги; trial запускается после описания |
| Pillow: декодирование, EXIF, ограничение24MP/10MB | Отдельно выбрать обработку изображений, совместимую с V8 | Сохранить нормализацию, лимит пикселей и два входа для объединения; одной проверки MIME недостаточно |
| Локальная SQLite, три успешных результата один раз на пользователя | SQLite платформы, схема пользователя/квоты/задания | Объединение и любая функция стоят1 попытку, повторная генерация — ещё1; дубль/ошибка не списывают дважды |
| Один durable worker и состояния queued/running/review | Подтвердить очередь/время жизни; затем выбрать исполнение | Сбой после отправки запроса не создаёт повторный платный вызов; неопределённый исход сохраняет резерв |
| Оригиналы24h, повторное использование, /delete | Telegram file_id либо ограниченное хранилище с ownership/TTL | Своё фото доступно после рестарта; срок проверяется перед отправкой; удаление не восстанавливает три попытки |
| OpenAI ключ в `.env`, фиксированная модель/medium/1024² | Документированное защищённое server secret + sdk.fetch multipart | Ключ не попадает в Git, JS, Mini App, URL и логи; реальный запрос успевает завершиться |
| Подписанный Mini App API, Pages предпросмотр | Endpoints с `ctx.initData.user` + статический hosting Telegram | Нет доступа по чужому job_id; неверный initData→401 на реальном endpoint, не CLI run |
| Существующие результаты, баланс и история | Согласованный импорт snapshot либо доступ к истории | Сравнить состояние до/после; не выдать три попытки повторно; выбрать один активный backend |

Это карта работ, не готовая замена Python-компонентов. В прототипе нет Image-запроса, генерационного ledger и пользовательских платежей.

## Подтверждённая платформа

GET [публичного `/capabilities`](https://cloud.telegram.org/capabilities) вернул HTTP200, `ok:true`, schema version1 и шаблоны SDK. Его SDK-reference совпал с файлом внутри официального CLI0.2.0. Есть JavaScript handlers, SQLite DSL, file download/upload, внешний HTTP и Mini App endpoints. Публичное чтение не требует токена и не подтверждает исполнение в аккаунте.

SQLite single-statement insert с unique key подходит для захвата события транспортного probe. Это не доказывает транзакцию нескольких операций для квоты и коммерческого ledger. Три попытки требуют отдельного атомарного перехода reserve→finish/fail/review; до подтверждения DB/runtime контракта его не заменяем набором независимых запросов.

## Что нужно выяснить перед платным запросом

1. Цена исполнения, бесплатная квота, ограничения и условия начисления платы.
2. Защищённое хранение/ротация серверного ключа OpenAI.
3. Wall-clock, CPU, память, timeout внешнего HTTP и поведение при завершении webhook. Текущий Python-клиент имеет timeout180s; на платформе это время не подтверждено.
4. Очередь, recovery, атомарная квота и ручное разрешение неоднозначного исхода без повторной оплаты.
5. Размер/backup/restore БД и медиа, TTL, нормализация фото и удаление.

Эти контракты не найдены в прочитанных SDK-reference и публичном descriptor. Отсутствие описания не доказывает отсутствие возможности. Если секреты или длительная генерация потребуют внешнего backend, Serverless будет только интерфейсом; полностью убрать сервер тогда не получится.

## Последовательность

1. **Подготовлено:** карта компонентов, отдельные модули probe, один offline smoke и независимое статическое ревью; результат проверки записывается в [verification.md](verification.md).
2. **Нужен доступ:** отдельный тестовый бот + его Serverless CLI Access token. Рабочий `@photo_editortest_bot` не переключается на этом этапе.
3. **Проверка без денег и личных фото:** реальный синтетический upload/download; concurrent duplicate; DB status; ограниченный долгий HTTP на контролируемом сервисе; настоящая проверка Mini App auth.
4. **Решение о платформе:** документированные цена, секреты, runtime/DB и privacy. До этого нельзя обещать бесплатный круглосуточный запуск.
5. **Затем:** портировать согласованный ledger и UX; один разрешённый Image PoC с измерением стоимости/времени; приватный snapshot и сверка трёх попыток; остановка polling перед включением cloud webhook; готовый rollback.

Альтернативный путь: обычный VPS сохраняет текущий Python/aiogram/Pillow и требует меньше переделок. Для показанных владельцем конфигураций LC-1 (1vCPU/2GB) — минимальный пилот, LC-2 (2vCPU/4GB) — предпочтительный запас, LC-3 (4vCPU/8GB) пока не обоснован измерениями. Это оценка ресурсов, не нагрузочный тест. Генерация выполняется в OpenAI API; расходы API оплачиваются отдельно от VPS.

Источник SDK: [Telegram Serverless](https://core.telegram.org/bots/serverless), [официальный npm CLI](https://www.npmjs.com/package/@tgcloud/cli). Подробные пределы и неизвестные условия: [telegram-serverless-study.md](telegram-serverless-study.md).
