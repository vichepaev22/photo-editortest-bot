# Живой ответ в личном диалоге Telegram

Контракт: PRD.md CR-TELEGRAM-LIVE-001, 22.10.2026. Mini App и MAX не затрагиваются.

В «Образе» нет текстового чат-агента: провайдер возвращает готовое изображение.
Поэтому переносим интерфейсную механику, а не подменяем обработку фото вымышленным
потоком рассуждений. Короткие меню мгновенные. На обработке — один редактируемый
статус, публичный план из функции и описания, реальные стадии, typing каждые4с.
Этапы подготовки/оформления могут пройти слишком быстро и не попасть в следующий
кадр; проценты и обещания точного времени не показываем. Не добавляем платный
текстовый запрос ради эффекта. На финале многоточие убирается, затем отправляется
исходный файл и по прежним правилам удаляются сообщения шагов.

## Код и зависимости

- `streaming_answer.py`: `StreamingAnswer.typing()` с finally, `_typing_loop`,
  `edit()` с интервалом1,2с и `retry_after`, `stream(AsyncIterable[str])` для реального
  будущего текстового потока. Чанки объединяются, промежуточное раскрытие300–600
  символов; финал нормализуется. Сообщение длиннее4096 UTF-16 единиц явно сокращается.
- `telegram_live.py`: адаптация к очереди изображений, краткий план по запросу,
  реальные стадии через `Service.progress`, очистка задач при завершении/остановке.
- `bot.py`: регистрация сообщения, `/stop`, приватная кнопка `live:stop:<job>`,
  запуск/завершение worker. Повтор одного запроса остаётся идемпотентным.
- `store.py`: один аддитивный флаг `jobs.telegram_silent`; атомарная отмена очереди
  и сохранение решения не доставлять автоматически после перезапуска.

Существующие aiogram3.31.0 / Python3.12+ / asyncio достаточны. Новых зависимостей
и env-переменных нет. Используются текущие приватные TELEGRAM_BOT_TOKEN,
OPENAI_API_KEY и IMAGE_MODEL; их значения не включаются в сообщения/логи.
Все новые sends/edits содержат `parse_mode=None`; пользовательские `<`, `>` и
разметка показываются как обычный текст. Логи — только типы ошибок.

## Остановка и деньги

`/stop` и кнопка работают только для своей задачи в личном чате. Для queued отмена
сериализована с claim одной SQLite-транзакцией: резерв возвращается один раз.
Для running отменяется только живой ответ и будущая автоматическая доставка.
Image-запрос не повторяется и не объявляется бесплатно отменённым: успешный
результат расходует прежнюю одну попытку, сохраняется и доступен через результаты.
Отправленный в Telegram файл нельзя отозвать остановкой интерфейса. `/cancel`
сохраняет старое значение «сбросить черновик».

Выбор новой функции/новый текстовый запрос прекращает старый живой ответ. Пока
предыдущий Image выполняется, прежний запрет двух одновременных задач сохраняется.
Поздняя кнопка старой задачи не затрагивает новую.

## Будущий текстовый агент

Хелпер готов принять реальные текстовые delta-чанки, но сейчас не подключается
к новой разговорной модели. Публичный JSON-контракт при добавлении такого агента:
`{"summary":"Краткий план действий для пользователя", "answer":"Текст ответа"}`.
`summary` — краткое объяснение действия, не скрытые мысли; для шаблонов и ответа
короче200 символов его не показывать. JSON нужен для структурированного ответа,
не является отдельной возможностью Telegram. Текущий фото-сценарий не вызывает
LLM с `thought` и не утверждает, что модель стримит текст.
